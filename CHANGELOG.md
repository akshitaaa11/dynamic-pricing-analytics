# Changelog

## Phase 0 — 2026-10-14
- Built the project skeleton: pinned requirements, Makefile, pipeline config, .gitignore, Spark helper, logging helper, and the required directory structure per README §5.
- Added placeholder modules for each project stage and a smoke test suite to confirm the repository layout and importability.
- Exit-check result (real data, 1,033,062-row silver table): `python -m pytest -q` passed 18/18; `python -m dpa.pipeline` ran end to end and regenerated the gold panel/features, forecast predictions and model, pricing holds, figures, metrics/SHAP CSVs and the data/model/final reports from computed values. Row/unit/revenue reconciliation matches the config contract.
- Forecast (test weeks 2011-09-05 to 2011-11-27, rolling origin: 3 blocks of 4 weeks, refit before each block; WAPE): moving_average_4 0.646, moving_average_13 0.651, LightGBM 0.665, seasonal_naive 0.959. LightGBM still does **not** beat the best baseline (the added rolling-mean features improved it from 0.680). The 80% interval from quantile models covers 77.7% of test product-weeks (mean width 87.2 units).
- Pricing: fixed-effects log-log elasticity (product + week effects) with empirical-Bayes shrinkage; 2,077 of 4,717 products identified. 139 get a price change (median -5.0%, within the +/-10% guardrail) and 4,578 are held with a reason. A revenue-search over retail-ending prices is only accepted when the gain holds across the 90% elasticity interval. Held-out check on 2,936 real test-period price changes: direction agreed 63.6% of the time (rank correlation 0.346).
- Fixed `.gitignore` (`models/` -> `/models/`) so `src/dpa/models/` is tracked.
- Remaining gaps: no direct 4-week-ahead model (forecasts are one-week-ahead, refit every 4 weeks), no error breakdown by demand tier or the November peak, no per-product SHAP.
